# 本地音乐播放器 + 音乐可视化引擎：项目执行方案（适配 7840HS + 核显）

## 1. 项目目标
开发一个桌面端本地音乐播放器，支持读取本地音频文件（至少支持 FLAC、MP3、WAV、M4A），并在播放时展示高质量、具有歌曲个性化风格的动态可视化效果。

该项目的核心不是“做一个普通播放器”，而是构建以下三部分的组合系统：
1. 本地音乐播放器
2. 音频特征分析引擎
3. 实时图形可视化渲染引擎

最终目标：
- 能稳定播放本地音频
- 能显示与音乐同步的动态可视化效果
- 不同歌曲具有不同的整体视觉风格
- 支持暂停、拖动进度、切歌后视觉同步不乱
- 代码结构清晰，可继续扩展更多主题与特效

---

## 2. 项目定位
这是一个“音频分析 + 可视化渲染 + 桌面播放器 UI”的综合项目。

建议采用“先做可运行 MVP，再逐步增强视觉”的策略，避免一开始陷入过度设计。

推荐先做 Python 桌面端原型，等第一版稳定后，再考虑是否重构渲染层或迁移部分模块。

---

## 3. 核心设计思想

### 3.1 两类音乐特征

#### A. 瞬时特征（实时驱动动画）
用于决定“当前这一刻画面怎么动”。

典型特征：
- 音量 / RMS
- 低频、中频、高频能量
- onset / 瞬态强度
- beat / 节拍点
- spectral centroid / 频谱重心

典型映射：
- 音量增大 -> 主环放大、亮度增强
- 低频增强 -> 大尺度波动、底部冲击
- 高频增强 -> 尖刺、闪点、粒子噪声
- 瞬态增强 -> 局部爆发、短暂闪光
- 节拍命中 -> 全局脉冲、镜头震动、环形冲击波

#### B. 全局特征（决定歌曲整体气质）
用于决定“这首歌整体长什么样”。

典型特征：
- 平均节奏快慢
- 低/高频整体占比
- 明亮/厚重/柔和/尖锐倾向
- 动态范围
- 音色统计特征（如 MFCC 统计量）

典型映射：
- 主色调
- 粒子密度
- 线条粗细
- 环的数量
- 扭曲程度
- 特效风格（赛博、梦幻、故障、宇宙等）

### 3.2 项目最终逻辑
每首歌的视觉表现 =
- 全局特征 -> 决定视觉 DNA
- 瞬时特征 -> 决定播放时每一刻的动态行为

## 4. 技术路线建议

### 4.1 建议首选技术栈（第一版）
#### 语言
- Python 3.11+

#### 桌面 UI
- PySide6

#### 音频播放
优先顺序：
1. PySide6.QtMultimedia
2. VLC Python 绑定（仅当 QtMultimedia 格式支持不稳定时备用）

#### 音频分析
- librosa
- numpy
- scipy
- soundfile
- mutagen（metadata）

#### 渲染
二选一：
- 方案 A：VisPy（更快起步）
- 方案 B：ModernGL（更利于后续 shader 和高级特效）

#### 测试与工程化
- pytest
- logging
- ruff / black（可选）

## 5. 关键现实约束：适配 7840HS + 核显

### 5.1 结论
该项目第一版和第二版在 7840HS + 核显环境下完全可做，不需要独立高性能 GPU。

必须明确：
- 本项目第一版不是“大模型推理项目”
- 核心负载主要是音频分析 + 中轻量图形渲染
- 一首 4 分钟歌曲的离线分析负担很小
- 真正影响体验的是渲染特效复杂度，而不是歌曲长度本身

### 5.2 对方案的修改
必须采用以下策略：
- 采用“离线预分析 + 播放时读取缓存”模式
- 首次导入歌曲时分析音频并写入缓存文件
- 播放时不重复做重计算，只做轻量插值、平滑、事件触发
- 默认目标帧率设为 60 FPS；性能不足时允许降到 30 FPS
- 默认做 2D / 2.5D 风格可视化，不做重型 3D 体渲染

第一版不要做：
- 不要做深度学习风格识别
- 不要做实时模型推理
- 不要做复杂流体模拟
- 不要做几十万粒子级别特效
- 不要做高成本 bloom 后处理链

可以保留但延后：
- glow
- 拖尾
- 中等规模粒子
- 多层环
- 背景星点
- 简单镜头震动

### 5.3 关于“CPU 推理”
第一版严格来说不需要“推理”。

更准确地说：
- 你需要的是数字音频特征提取
- 这部分用 CPU 即可
- 若将来加入歌曲风格分类或 embedding，建议只在首次导入时离线运行一次并缓存结果

## 6. 版本规划

## Phase 1：MVP（必须完成）
目标：做出一个“能用、能播、能跟着动”的版本。

### 功能要求
- 加载本地音乐文件或音乐目录
- 播放 / 暂停 / 停止
- 进度条拖动
- 上一首 / 下一首
- 显示曲名、专辑、封面（有则显示）
- 显示基础可视化

### MVP 可视化最低要求
- 一个主圆环或其他核心几何体
- 低/中/高频驱动不同层级形变
- 节拍触发全局脉冲
- 音量驱动整体亮度或缩放
- 暂停/拖动/切歌后视觉时间轴保持同步

### MVP 验收标准
- 打开任意支持格式音频后可正常播放
- 视觉在播放时稳定刷新，无明显卡死
- 暂停时视觉停止或进入受控 idle 状态
- 拖动进度后视觉能跳到正确时间位置
- 切歌后不会沿用上一首歌的视觉状态缓存

## Phase 2：增强版（建议完成）
### 新增功能
- 本地曲库扫描
- 播放列表
- 随机播放 / 单曲循环 / 列表循环
- 可视化主题切换
- 设置页
- 歌曲分析缓存

### 视觉增强
- 粒子系统
- 冲击波
- 多层同心环
- 背景星点 / 噪声流场
- 高频细碎辉光
- 节拍触发镜头微震
- 拖尾

### 工程增强
- 首次导入歌曲时离线分析并缓存
- 再次播放时直接读取缓存
- 缓存与音频文件哈希绑定

## Phase 3：高级版（可选）
- 为每首歌自动生成视觉 DNA
- 段落检测
- 多主题系统
- shader 后处理链
- 全屏表演模式
- 导出视频片段

## 8. 数据流设计
### 首次导入歌曲
1. 选择歌曲或扫描目录
2. 读取 metadata 和封面
3. 音频分析模块离线提取特征
4. 保存特征缓存到本地
5. 在曲库中登记

### 播放歌曲
1. 播放器开始播放
2. UI 持续获取当前播放时间
3. 可视化引擎根据当前时间读取对应特征帧
4. 将特征映射为动画参数
5. 渲染器每帧刷新画面

### 拖动进度条
1. 播放器跳转到目标时间
2. 可视化同步模块重定位到该时间点
3. 清理上一时间点残留状态
4. 从目标时间点恢复视觉

---

## 9. 首版必须提取的特征
第一版只做以下特征，避免过度复杂：
- RMS / loudness
- STFT 或 mel-spectrogram
- 三段频带能量（低/中/高）
- onset strength
- beat positions
- spectral centroid
- 全局统计（平均能量、平均节奏、频带占比、动态范围）

---

## 10. 特征到动效映射表（首版）
- RMS -> 主体缩放、亮度、发光强度
- 低频 -> 主环大幅起伏、底部能量脉冲
- 中频 -> 环表面波纹、次级轮廓变形
- 高频 -> 尖刺、噪点、闪光粒子
- onset -> 局部爆发、短促亮闪
- beat -> 全局冲击波、镜头微震、整体脉冲
- spectral centroid -> 颜色偏冷/偏暖、锐利程度
- 全局统计 -> 主题色、粒子数量、线条粗细、主风格

## 11. 开发要求（给 Claude Code）
Claude Code 必须遵守以下开发原则：
- 第一优先级：稳定可运行
- 第二优先级：播放与视觉同步正确
- 第三优先级：在 7840HS + 核显上性能可接受
- 第四优先级：架构可扩展

明确禁止：
- 把所有逻辑写进一个文件
- 把播放时间与视觉时间轴分离到无法同步
- 首版引入不必要的 AI 模型
- 首版堆砌高成本特效
- 缺少异常处理与日志
